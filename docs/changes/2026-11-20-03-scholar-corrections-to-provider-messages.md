# 2026-11-20 · Scholar correction requests go to the provider (provider › Messages)

**Asked (owner):** when a scholar wants their information updated, the message must be received by the provider, not the admin, so providers need a section for received messages.

## What changed
- **New table `scholar_messages`** (migration `2026_11_20_000003_create_scholar_messages_table`, model `App\Models\ScholarMessage`): `scholar_id` (which scholarship → which provider), `user_id` (sender), `topic` (`ScholarMessage::TOPICS`: personal / contact / school / scholarship / other = the Profile cards), `message`, `reply`, `replied_by`, `replied_at`, `reply_emailed_at`, `handled_at`. Separate from `contact_messages`, so the admin never sees them. `Scholar::messages()`.
- **Scholar Profile › Request a correction** (`#corrections`, `scholar.profile.correction`, POST `/scholar/profile/corrections`, throttle 5/10 min): pick the scholarship (only when there is more than one; must be one of the scholar's OWN, rule 4), what needs correcting, and the message. "Your requests" lists what was asked with the provider's reply and status (Waiting for your provider / Answered / Done). Validation errors use the `correction` error bag. Without a scholarship there is no form.
- **Provider › Messages** (`ProviderMessageController`, `provider.messages`, sidebar under Main with an "open" badge = `navCounts['messages']`): Open / All, each message shows the scholar (link), scholarship, Scholar ID, e-mail, date; **Reply** (saved on the message, shown on the scholar's Profile, e-mailed with `App\Mail\ScholarMessageReply` / `emails.scholar-message-reply`, Reply-To = the provider account; marks handled; a failed or test-mode e-mail keeps the saved reply and says so); **Mark handled / Reopen**; **Open the profile to correct it** (`?edit=<topic>` for personal / contact / school / scholarship). Everything goes through `ProviderScope::messages()` / `message($id)`, so another provider's message is 404.
- **Scholar Help:** the BAKR-team form no longer offers "Scholarship info needs updating" (`ScholarPortalController::helpTopics()`, refused server-side too); the FAQ and the message card point to Profile › Request a correction. Provider Help has a FAQ about Messages.
- `.am-reply` / `.am-sent` styles moved from `bakr-admin.css` to `bakr-dashboard.css` (shared), plus `.am-meta`.

- **Fix: same-page links inside the portals** (`public/js/bakr-core.js`): the shared `#hash` link handler scrolled the window, but on desktop the portal content scrolls inside `.dash-main`, so "Request a correction" (`#corrections`) did nothing. It now scrolls the nearest scrolling container (window only when there is none); the same applies after the redirect to `/scholar/profile#corrections` and to every other in-portal `#` link on `layouts.app` pages (scholar and student portals).

- **Success modal instead of an alert (owner: "replace the alert with a modal that shows sending the message is a success", and the same where it fits):** new `Controller::sent()` + `partials/portal/sent-dialog` (included in the scholar, student, provider and admin layouts; opened on load by the existing `data-auto-open` code in `bakr-dashboard.js`; `<noscript>` fallback). Applied to every "it was sent" success: scholar "Request sent", "Message sent" on the student / scholar / provider Help pages, "Reply sent" (provider Messages, admin Messages), "Reset link sent" (scholar Settings, admin Accounts), "Login details sent" (provider › Resend login details). Failures, test-mode mail and saves keep their alerts. New `.dash-confirm-icon.is-ok` (+ dark). Tests now check `session('sent')` and that the modal renders once.

- **No more "· + pill" rows (owner: "replace all the · + pill combo … with a more proper design that doesn't scream AI"):** new shared `.dash-meta` (details spaced by CSS with small icons, no "·") and `.dash-status` (coloured dot + word instead of a filled pill), `.dash-status-group`, `.am-head` in `bakr-dashboard.css` (colours = the `--viz-*` tokens, so dark mode follows). Converted: scholar Overview (your scholarships), My scholarship (header, stipend list, status), Requirements (not-open list, document rows, file line), Profile (identity row, status, Your requests); provider Overview (recent scholars, uploads to review), Scholars list (person, campus/year, status, stipend, requirements cells), scholar profile (identity rows, status, overdue list, stipend table), Requirements (accordion rows, requirement items, review queue now passes `whoScholarship` instead of joining with "·"), Disbursements (person, status), Messages; admin Messages. Labels/tags keep `.dash-pill`. Checked in light and dark with headless Chrome screenshots (preview files deleted).
