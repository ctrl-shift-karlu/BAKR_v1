# 2026-11-21 · Phones: smaller fluid text, no zoom-out, folded profile cards; scholar notifications; live About totals

Owner's requests: lighter phone screens (text and elements filled the screen), no element wider than the screen (pages could zoom out), the Overview "Requirements" button not working on phones, collapsible profile cards, notifications to scholars about their status and their correction requests, About analytics that follow the database. Existing logic unchanged.

## Changes

1. **Fluid type scale** (`bakr-core.css`, `bakr-dashboard.css`, `student-auth.css`, identical): `--text-md`, `-title`, `-lg`, `-xl`, `-2xl` are `clamp()`: a step smaller on a 360px phone (15 · 16.5 · 18 · 20 · 25px), the old sizes from 1200px. `xs` / `caption` / `sm` never shrink (12px minimum kept). Headings with their own clamp also shrink: portal hero `h1`, topbar `h1`, `.nx-h2`, home hero, page hero. Public-site labels under 12px (login menu header, footer `h5`, welcome kicker) now use `--text-xs`.
2. **Phone block** at the end of `bakr-dashboard.css` (≤575.98px): shorter hero (no breadcrumb, the mobile bar has it; subtitle clamped to 2 lines; buttons share the row), compact KPI tiles (no forced 4-line labels: 129px → ~90px), 12px gaps, smaller card titles and fold headers, dialogs nearly full width.
3. **Zoom-out bug:** the provider Overview chart legend ran 19px off a 320px phone. Legend = one shrinkable column and drops under the donut on narrow cards. Safety net: `html, body { overflow-x: clip }` (clip keeps `position: sticky`), media max-width 100%. Probed every portal + public page at 320 / 360 / 1400px: nothing wider than the screen.
4. **"Requirements" button on phones:** it works in Chrome at every width (tested by tap hit-testing). The likely phone cause is iOS's "first tap only shows the hover" when a hover moves the element: on touch screens (`@media (hover: none)`) buttons and tiles no longer lift on hover, and controls get `touch-action: manipulation` (no double-tap zoom delay).
5. ~~Scholar Profile cards fold~~ **undone the same day (owner):** the Profile keeps its plain cards, two per row (one column on phones), now with ids (`#personal`, `#contact`, `#school`, `#scholarship`, `#requests`) for notification links. `bakr-dashboard.js` still opens a folded `details.ms-fold` named in a link (used by My scholarship).
6. **Notifications to scholars:** table `notifications` (Laravel standard, migration `2026_11_21_000001`), `App\Notifications\ScholarUpdate`, `App\Services\ScholarNotifier`, e-mail `emails/scholar-update`. Sent when the provider changes the status (Terminated / Inactive / Active: in-portal + e-mail), saves a profile card the scholar had an OPEN correction request about and something really changed (in-portal + e-mail; the request stays open for the provider to close), and replies (in-portal only; the reply is already e-mailed). Shown on the scholar Overview › "Updates from your provider" (latest 6, "New" until seen); sidebar badge on Overview; opening Overview marks them read. A failed e-mail never blocks the provider's action.
7. **About totals** (`PublicAnalyticsService`): "Campuses / Programs represented" (counted only groups ≥ 10, so 0) replaced by **Scholarships listed** and **Scholars monitored**, live from the tables. The accounts trend shows running totals of all accounts (the latest equals the headline total, so nothing was private); a zero-account trend no longer divides by 0. Charts whose groups are all under 10 say "Not enough students yet…" instead of looking stale. Group hiding (< 10) unchanged.
8. Shorter wording on the scholar Overview (hero subtitle, KPI labels, stipend hint). `sw.js` `VERSION` → `bakr-v3`.
